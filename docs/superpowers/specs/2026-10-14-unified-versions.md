# 新旧版合一设计

把 `37f/PixivBatchBookmark-Windows` 原 WPF 旧版接入
`37f/PixivBatchBookmark-PySide6` 新版。一个程序包默认启动新版，
一个“切换到旧版”按钮显示实际旧版，旧版一个“换回新版”按钮返回新版。

## 架构

保留旧版源码、资源、测试、许可于 `legacy/`。Qt 入口用 QProcess 按需启动
WPF 子进程，通过匿名 stdio 管道协调窗口：父命令 LEGACY/EXIT，子通知
READY/SHOWN/MODERN。旧版 Loaded 后保持隐藏并发送 READY；父进程发送 LEGACY，
旧版显示并发送 SHOWN 后新版才隐藏。返回新版先隐藏旧版。
反复切换复用两个窗口，保留各自输入、日志、列表、壁纸、模式及会话。
控制管道不传账号、Cookie 或用户输入。相比重写成 Qt，此方式保留实际旧版；
相比两个快捷方式，统一入口能协调任务互斥和退出。

## 行为

- 两个版本的切换按钮在纯壁纸模式中仍可见。
- 运行/暂停中的任务不能切换，旧版登录检查也不能切换。
- 新版登录对话框显示时禁用切换，防止隐藏仍在登录的窗口。
- 旧版缺失、启动失败、超时或崩溃时恢复新版并提示原因。
- 浏览器 Cookie 不迁移，保留 Chromium/browser 与 WebView2 配置。
- 新版自定义代理只影响新版，旧版保持 Windows 系统代理。
- 正常关闭任一主窗口结束整个应用；关闭新版先等待旧版退出。
- 父进程死亡产生 EOF，旧版停止批次，等待当前核验/恢复后退出。
- 尚未激活的旧进程启动或退出超时可清理；一旦已激活，不强杀可能进行中的
  操作。退出超时恢复日志等界面，暂时禁用收藏和切换直到旧版结束。
- 不强杀进行中的写操作。独立旧版启动保持单实例，隐藏返回按钮。
- 集成旧版也使用原 WPF mutex，避免与独立旧版共享配置同时运行。

## 构建及验证

Windows 10/11 x64；Python 3.12、PySide6 6.10.2、.NET 10 SDK。
保留 WPF 程序集名称 PixivBatchBookmark，避免破坏 pack URI。
统一脚本先测试/发布自包含 WPF 再打包 Qt，旧版完整输出复制到
`dist/PixivBatchBookmark/legacy/`。发布包无需 Python 或 .NET SDK。
源码启动脚本按需构建旧版。

验证现有业务套件、真实进程管道双向切换/复用/超时/崩溃/关闭、Qt 按钮、
WPF UI 状态保留和忙碌保护、Windows 真实跨框架切换及完整发布包。
所有测试离线，不操作真实 Pixiv 账号。本地 Linux 不能执行 WPF，使用 Windows CI。
