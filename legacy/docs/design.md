# Pixiv 批量收藏 Windows 版设计

用户目标：把 Android 版 v0.1.5 已确认的收藏规则做成中文 Windows 桌面项目，交付可构建源码、构建说明及在本机可以验证的运行包。未取得 Android 源码，因此这是功能重实现。

## 范围与技术选择

- C# / .NET 10 / WPF；WebView2 负责官方网页登录。相较 Python / Qt，Windows 原生界面与发布包更紧凑；代价是依赖 WebView2 Runtime。
- 支持插画和漫画作品 ID、作品 URL、旧式 illust_id URL、带 pixiv id 标注的文本；不把用户 ID、小说 ID、日期或标题中的数字当成作品 ID。
- 输入、解析预览、公开/私密互斥选择、批量收藏、批量取消、停止任务、中文任务日志。
- 顺序处理作品，每项间隔 1.5 秒。HTTP 超时 30 秒；不自动重试写请求。
- 内置网页使用 Windows 系统代理设置。第一版不额外实现代理管理、自动读剪贴板、拖放或暂停恢复。

## 登录与接口

用户在 Pixiv 官方网页中输入账号密码；程序不记录密码。WebView2 使用 `%LOCALAPPDATA%/PixivBatchBookmark/WebView2` 保存浏览器登录状态，Cookie 只在内存中传给 HTTP 客户端，不导出明文 Cookie 文件。
登录检查同时验证用户身份和 CSRF 令牌；缺一不可。只接受 pixiv.net 官方来源的身份数据。批次开始前重新检查登录与令牌。
收藏使用 Pixiv 网站内部 Ajax 接口；这些接口没有稳定性承诺。身份或安全令牌失效、429 限流、服务端错误、响应格式不符时停止批次并提示用户。

## 收藏状态规则

- 未收藏：添加目标模式，读回状态确认。
- 已是目标模式：跳过，不写入。
- 模式不同：读取并保存原收藏标签，取消原收藏，确认取消，再添加目标模式并核验。停止按钮只在作品之间生效，不把正在转换的作品留在中间状态。
- 批量取消：未收藏跳过；已收藏取消并核验。
- 转换过程中重新添加失败：先核对真实状态；若确实未收藏，尝试恢复原模式与标签。恢复成功仍记作本项失败，告知用户转换未完成；无法确定状态或恢复失败则停止整个批次，明确列出作品 ID。绝不静默继续。
- 先取消再重建会产生新的收藏记录；原收藏时间及记录 ID 无法保留。

## 验证边界

用离线状态模型测试两向转换、标签保留、取消核验、恢复失败、取消请求及输入解析；用 HTTP 响应夹具核对请求格式、令牌解析、无权限和限流处理。真实账号登录、验证码及收藏修改需要用户自行验收，本次不冒充已经验证。
